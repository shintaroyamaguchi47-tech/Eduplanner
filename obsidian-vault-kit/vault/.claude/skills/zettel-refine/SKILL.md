# 永久ノートへの昇格

走り書きは「あとで読むと意味が分からない」。永久ノートは「10年後の自分が読んで分かる」。
その差を埋めるのがこのスキル。**要約ではなく、書き直し**である。

## 昇格の条件

次を**すべて**満たすものだけを `30_Permanent/` に上げる。満たさないものは
`00_Inbox/` に残すか `90_Archive/` へ送る。

- [ ] 主張が1つに絞れる（2つあるなら2ノートに割る）
- [ ] 出典や文脈が無くても、その文章単体で意味が通る
- [ ] 自分の言葉になっている（原文のコピーではない）
- [ ] 既存の永久ノートと重複していない

## 手順

1. **重複を潰す**

   ```
   rg -il "<主張のキーワード>" 30_Permanent/ 40_MOC/
   ```

   同じ主張のノートがあれば、新規作成せずそちらを更新する。
   微妙に違うだけなら、既存ノートに `## 反例` や `## 補強` として追記する方が価値が高い。

2. **タイトルを主張そのものにする**

   タイトルを読んだだけで中身が分かる、完全な文にする。

   - 良い: `問いを与えるより問いを作らせる方が定着する.md`
   - 良い: `板書は記録ではなく思考の足場である.md`
   - 悪い: `問いについて.md` / `板書メモ.md`

3. **本文を書く**

   ```markdown
   ---
   title: <タイトルと同じ文>
   created: <元メモの作成日>
   updated: <今日>
   type: permanent
   tags: []
   status: seed
   ---

   ## 主張
   1〜3文で言い切る。条件や留保はここに書かない。

   ## なぜそう言えるか
   根拠・経験・出典。他人の考えは `>` で引用し出典を添える。

   ## 反例・限界
   この主張が成り立たない場面。ここが書けているノートは強い。
   思いつかなければ「未検討」と書く。

   ## 出典
   - [[20260829-著者-タイトル]]（元になった文献ノート）

   ## 関連
   - [[別の永久ノート]] — 対立する / 補強する / 前提になる、を明記
   ```

4. **双方向リンクにする**

   新しい永久ノートから既存ノートへリンクを張ったら、**張られた側にも**
   `## 関連` に一行を追記する。片方向のリンクは後で辿れない。
   （既存ノートへのこの追記は許可されている追記操作）

5. **MOC に載せる**

   該当テーマの MOC が `40_MOC/` にあれば、そこにリンクを1行足す。
   無ければ「MOC を作るか」を提案する（`moc-builder` スキル）。

6. **元メモを処理する**

   元が `00_Inbox/` の走り書きなら `90_Archive/` へ移動する。
   `20_Literature/` の文献ノートは**残す**（出典として参照され続けるため）。

7. **報告する**

   作った永久ノート、更新した既存ノート、移動したファイルを列挙する。

## やらないこと

- 1ノートに複数の主張を詰めない。分割する。
- 昇格条件を満たさないものを無理に上げない。「まだ早い」と言ってよい。
- `status: evergreen` を自分の判断で付けない。初期値は必ず `seed`。
