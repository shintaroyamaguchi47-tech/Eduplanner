# Vault 横断検索

**この Vault に書いてあることだけを根拠に答える。** 一般論で埋めない。
書いていないことは「書いていない」と言う。それが第二の脳の信頼性を作る。

## 手順

1. **検索語を広げる**

   利用者の言葉そのままでは引っかからないことが多い。同義語・表記ゆれを2〜4語作る。

   例:「評価」→ `評価|ルーブリック|観点別|形成的`
      「問いづくり」→ `問い|発問|課題設定|Question`

2. **段階的に絞る**

   ```
   rg -il "<語1>|<語2>" --glob '*.md'            # まずファイル名を取る
   rg -i "<語1>|<語2>" -C2 --glob '*.md' | head -100   # 前後2行で当たりを見る
   ```

   ヒットが多すぎるときはフォルダで絞る（`30_Permanent/` `40_MOC/` から見るのが速い）。
   ヒットが0なら、検索語を変えて最低2回は試してから「無い」と結論する。

3. **本文を読む**

   当たりを付けたノートは、抜粋ではなく全文を読む。フロントマターの
   `status` と `updated` を見て、古い・未熟なノートかを判断材料にする。

4. **答える**

   ```markdown
   ## 結論
   Vault の記述から言えることを3行以内で。

   ## 根拠
   - [[ノート名]]（30_Permanent, updated 2026-05-12）
     > 該当箇所の引用

   ## Vault に書かれていないこと
   - 今回の問いのうち、ノートが答えていない部分を明示する
   ```

   - **すべての主張に `[[ ]]` リンクを付ける。** リンクの無い断定はしない。
   - 古いノート（`updated` が1年以上前）を根拠にするときは、その旨を添える。
   - ノート同士が矛盾していたら、まとめずに**両方出して矛盾を指摘する**。
     これは欠陥ではなく、考えが更新された痕跡なので価値がある。

5. **副産物を提案する**

   検索の結果、次のいずれかに気づいたら1行で提案する（勝手に実行しない）。

   - 同じ主張のノートが3つ以上に散らばっている → 統合を提案
   - 関連ノートが5つ以上あるのに MOC が無い → `moc-builder` を提案
   - 明らかな空白（考えたことが無い論点）がある → 指摘する

## やらないこと

- Vault に無いことを、一般知識で補って答えない。補うなら
  「これは Vault 外の一般知識です」と明示して分ける。
- 検索1回で「見つかりません」と結論しない。
- ノートを勝手に作らない・書き換えない。このスキルは読み取り専用。
